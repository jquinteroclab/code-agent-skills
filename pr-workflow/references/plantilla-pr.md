# Plantilla de descripción del Pull Request

Usar siempre esta estructura en la descripción del PR:

```markdown
## ¿Qué se hizo?
- Breve descripción de los cambios

## ¿Por qué?
- Motivo del cambio

## ¿Cómo probarlo?
- Pasos para verificar

## Checklist
- [ ] Tests pasan
- [ ] Se revisó el código
- [ ] No rompe funcionalidades existentes
```

## Notas de uso

- Completar todas las secciones de forma clara y concisa.
- En el Checklist, marcar con `[x]` lo que corresponda.
- Si el cambio es muy simple se puede resumir, pero la estructura se mantiene.
